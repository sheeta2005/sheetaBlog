# 网络分层模型

## 一、为什么要分层

分层让每一层专注解决一类问题，通过接口给上一层提供服务。例如 HTTP 关心请求语义，TCP 关心可靠字节流，IP 关心跨网络寻址与转发。替换链路技术时，不必重写所有应用协议。

OSI 七层是理解模型；实际互联网通常按 TCP/IP 分层讨论。常见五层教学模型又把链路中的物理传输单独拆出，不应把“四层”和“五层”当成协议冲突。

## 二、模型对照

| OSI 层 | TCP/IP 对应 | 例子与职责 |
| --- | --- | --- |
| 应用、表示、会话 | 应用层 | HTTP、DNS、数据表示与应用会话 |
| 传输 | 传输层 | TCP、UDP，进程间端到端通信 |
| 网络 | 网际层 | IPv4、IPv6，寻址和路由 |
| 数据链路、物理 | 链路层 | Ethernet、Wi-Fi，局部链路传输 |

TLS 常被画在 HTTP 与 TCP 之间以帮助理解安全封装，但它不是 TCP/IP 模型中独立规定的一层。HTTP/3 使用 QUIC，不能硬套所有 HTTP 都运行在 TCP 上。

## 三、封装与解封装

应用生成数据，传输层加入传输控制信息，IP 层加入源和目的地址，链路层组成帧送到下一跳。接收方反向解析各层信息，再把应用数据交给目标服务。

路由器转发时通常更换下一跳链路封装，端到端 IP 目的地址通常保持不变；NAT 等机制会改变这一简单模型中的部分地址或端口。

## 四、地址各自解决什么问题

**IP 地址** 用于网络中的定位与路由；**端口** 帮助传输层区分服务端点；**MAC 地址** 用于特定链路上的帧交付。访问远端服务器时，当前以太网帧的目的 MAC 通常是下一跳网关，不是远端服务器的 MAC。

TCP 连接常用源 IP、源端口、目的 IP、目的端口四元组标识；若同时讨论不同传输协议，可使用包含协议的五元组。

## 五、面试简答与追问

**简答：** 分层通过职责与接口降低耦合，传输层处理端到端通信，IP 层处理路由，链路层负责当前链路交付。

**追问：TCP 可靠，HTTP 请求就一定成功吗？** 不一定。应用可能超时或返回错误，连接也可能中途断开；传输字节成功不等于业务事务成功。

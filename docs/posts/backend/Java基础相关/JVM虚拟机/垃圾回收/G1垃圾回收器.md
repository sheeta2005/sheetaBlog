# G1垃圾回收器

## 一、基础概述

G1 将堆划分为相同大小的 Region，兼顾吞吐与暂停目标。它是分代收集器，年轻代和老年代仍然存在，只是没有必须连续相邻的固定边界。

JDK 9 将 G1 设为服务端默认收集器；本文以 JDK 21 HotSpot 为基线。默认选择还需结合具体运行环境，不应将历史客户端模式与现代服务端一概而论。

## 二、Region 与对象分配

| 区域 | 主要用途 |
| --- | --- |
| Eden | 普通新对象的主要分配区域 |
| Survivor | 年轻对象经历回收后继续存活 |
| Old | 晋升或其他老年代存活对象 |
| Humongous | 达到特殊大小阈值的大对象，属于老年代 |

JDK 21 HotSpot 源码按对象总大小严格大于 Region 一半判断 Humongous，分配时可能需要连续 Region。因此“所有对象先进入 Eden”和“G1 绝不会有碎片问题”都不准确。

部分调优文档用“大于或等于一半”概述阈值；讨论恰好等于一半的边界时，本文以对应版本源码的比较条件为准，并计入对象头与对齐。

疏散复制把存活对象移到其他 Region，释放参与回收的源 Region，但大对象分配还可能受到连续空间与浪费的影响。

## 三、回收周期与对象去向

### 1. Young 回收

年轻代回收会暂停应用线程，疏散 Eden 与 Survivor 的存活对象。对象按年龄与空间等条件复制到 Survivor 或晋升到 Old，不是所有对象都只在两个固定 Survivor 区之间交换。

### 2. 并发标记

老年代占用达到相应阈值时，G1 安排 Concurrent Start，配合年轻代暂停启动标记。IHOP 可根据分配与标记历史自适应变化，不是“固定做几次 Young GC 后必定标记”。

标记的大部分工作与应用并发；Remark 暂停完成标记相关工作，Cleanup 参与决定后续回收。SATB 记录维持标记开始时的可达性视图，不能说 Remark 保证清掉所有并发期间新变成的垃圾。

### 3. Mixed 回收

Mixed 在年轻代回收之外，选入部分预计回收收益较高的老年代 Region，通常分多次逐步完成。

**年轻对象** 移动到 Survivor 或 Old；**老年代对象** 移动到其他 Old Region。原笔记中“所有对象都复制到 Survivor”的说法应纠正。

## 四、暂停目标与 Full GC

`MaxGCPauseMillis` 指导工作量选择，是软目标而非实时上限。目标过紧可能缩小每次工作量、增加频率或损失吞吐，必须结合业务结果验证。

当可用空间不足、疏散失败或回收进展赶不上分配等情况下，可能出现 Full GC 或分配失败相关处理。不是任何并发标记波动都会立即触发 Full GC。

持续空间压力应检查回收后存活量、分配速率、大对象与堆余量，而不是只缩短暂停目标。

## 五、面试简答与追问

**简答：** G1 按 Region 管理分代，通过年轻代回收、并发标记与 Mixed 疏散逐步回收老年代；大部分标记并发，但复制等阶段仍暂停，目标不能保证绝对上限。

**追问：G1 的“垃圾优先”是什么？** 根据预计回收收益与代价选择部分老年代 Region，不是按对象创建时间简单排序。

# 常量池与字符串驻留

## 一、三种概念不要混在一起

| 概念 | 主要内容 | 所属层次 |
| --- | --- | --- |
| class 文件常量池 | 字面量、类名、字段和方法等符号信息 | 文件格式 |
| 运行时常量池 | 类或接口运行时使用的常量与引用信息 | JVM 运行时结构 |
| 字符串驻留池 | 用于复用规范化 String 实例 | 字符串对象复用机制 |

运行时常量池并不是只存 String 的容器。字符串对象的位置与常量池引用、类元数据的位置也不是同一个问题；在现代 HotSpot 中 String 实例属于堆对象。

## 二、符号引用如何被使用

编译器并不知道某个方法最终在运行时的具体内存地址，于是在 class 中记录类名、方法名和描述符等信息。加载与链接过程中，JVM 按规则解析所需引用，解析时机可以随实现和使用过程变化。

`javap -v` 能查看 class 常量池条目，帮助区分方法引用、UTF-8 数据和字符串常量。文件中的 UTF-8 条目不是已经创建好的 Java String 实例。

## 三、字符串比较的例子

```java
String a = "mint";
String b = "mi" + "nt";        // 编译期常量表达式，得到相同字面量。
String c = new String("mint"); // 显式创建不同实例。
System.out.println(a == b);         // true：同一驻留字符串。
System.out.println(a == c);         // false：引用不同。
System.out.println(a.equals(c));    // true：内容相同。
System.out.println(a == c.intern());// true：返回内容对应的驻留实例。
```

`==` 比较引用是否相同，`equals` 比较 String 内容。变量参与的运行时拼接不能直接套用编译期常量折叠结论，除非表达式满足常量表达式规则。

## 四、intern 的边界

`intern()` 返回与当前内容对应的规范化驻留引用，不代表“无论是否已有相同内容，都把当前实例移动到某个区”。池中已有内容相同的字符串时，返回已有引用。

对大量动态且不重复的文本滥用驻留，会增加查找与存储压力。是否节省内存要看重复度和对象生命周期，不能为了“减少 String”一律调用 `intern()`。

## 五、面试简答与追问

**简答：** class 常量池描述文件中的常量和符号，运行时常量池支持类的执行，字符串驻留用于相同内容实例的规范化复用。三者相互关联但不是同一个池。

**追问：new String 一定创建两个新对象吗？** 不能固定回答。显式创建的实例与字面量对应实例要分开，字面量可能早已存在；JIT 也可能影响实际分配。

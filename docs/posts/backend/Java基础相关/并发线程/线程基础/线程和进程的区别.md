# 线程和进程的区别

## 一、核心定义

进程通常是资源与隔离的容器，拥有自己的虚拟地址空间及相关资源；线程是进程内的执行流。在 Linux 等系统中，内核按可调度任务安排运行，不能同时把“进程”和“线程”都简单定义为唯一调度单位。

同进程的线程共享许多资源，但有独立的执行现场。共享带来通信便利，也要求对可变状态做好并发控制。

## 二、关键区别

| 维度 | 不同进程 | 同进程线程 |
| --- | --- | --- |
| 地址空间 | 通常隔离，可显式建立共享映射 | 共享代码、堆等地址空间 |
| 私有执行状态 | 各任务有自己的状态 | 各有栈、寄存器、程序计数状态 |
| 通信 | 管道、共享内存、Socket 等 IPC | 可通过共享对象通信 |
| 切换工作 | 通常还涉及地址空间上下文 | 一般不改变所属进程地址空间 |
| 故障影响 | 更便于隔离 | 共享错误可能影响整个进程 |

线程栈是逻辑上的线程私有执行区域，但仍在进程地址空间中；不能据此认为其他线程在所有语言环境下都物理无法触碰其内存。

## 三、切换成本不等于复制内存

进程切换并不复制全部堆、文件句柄或整张页表。系统保存恢复执行现场，切换相应地址空间上下文，期间可能产生 TLB、缓存与调度开销。

同进程线程省去部分地址空间工作，通常更轻，但跨核迁移、数据访问模式与缓存失效也影响实际成本，不能断言固定快多少倍。

## 四、多线程与多进程如何选择

Java 平台线程可以在多核 CPU 上并行执行计算，不能套用某些语言运行时限制，声称“计算密集只能用多进程”。

多线程适合需要共享状态的并发任务；多进程适合较强故障隔离、独立部署或不同运行环境。两者都可处理 IO 与计算，最终还受 CPU、内存、连接池和下游容量限制。

普通 Java 未捕获异常通常终止相应线程，不必导致整个 JVM 崩溃；本地代码致命错误或共享内存破坏则可能影响整个进程。多个进程也可能因共享外部资源或系统压力一起受影响，隔离不是绝对保证。

## 五、JDK 21 虚拟线程

虚拟线程由 JVM 调度，不是一条虚拟线程永久对应一条操作系统线程。阻塞任务可能借此获得更轻的并发，但不能突破 CPU 核数和数据库容量。

计算任务大量使用虚拟线程不会自动更快；JDK 21 还有 pinning 等需要核对的运行行为。这里讨论的是该版本，不把后续版本改进反套回来。

## 六、面试简答与追问

**简答：** 进程重点提供资源与隔离，线程提供进程内执行流。共享资源降低通信成本，也增加并发与故障耦合；切换主要保存执行状态，不复制整个内存。

**追问：线程共享哪些资源？** 通常共享堆、代码、进程文件描述符等；有自己的执行栈、寄存器状态和线程局部数据，但具体资源语义依平台而异。

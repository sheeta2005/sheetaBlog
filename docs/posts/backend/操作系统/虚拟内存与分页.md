# 虚拟内存与分页

## 一、虚拟地址不等于物理地址

进程看到的是虚拟地址空间，硬件与操作系统共同把虚拟地址映射到物理页。这样既能隔离进程，也能让地址空间布局不必依赖物理内存连续性。

分页把虚拟地址拆成页号和页内偏移。页表记录映射与访问权限；多级页表避免为整个稀疏地址空间一次分配庞大的平铺表。

## 二、一次内存访问的路径

1. CPU 生成虚拟地址，检查地址翻译缓存 TLB。
2. TLB 命中时直接使用缓存映射；未命中则进行页表遍历。
3. 映射存在且权限允许，访问对应物理页。
4. 映射缺失或权限不符，触发缺页异常，由操作系统决定补页、复制还是终止访问。

**TLB 未命中不等于缺页。** 页表可以有有效映射，只是翻译缓存没有记录。**缺页也不等于磁盘读取。** 首次分配、写时复制和文件调入涉及不同处理。

## 三、按需分配与写时复制

申请一大片虚拟地址不一定立刻占用等量物理内存。匿名内存常在实际访问时才分配物理页，这解释了虚拟内存很大但驻留内存较小的现象。

Linux `fork` 后父子进程可暂时共享某些物理页，并把可写页映射设为受保护状态。一方尝试写入时触发异常，内核为它复制页面，使修改相互隔离，这称为写时复制 COW。

## 四、常见指标与后端关联

| 概念 | 含义 | 误区 |
| --- | --- | --- |
| 虚拟内存 | 进程映射的地址空间 | 全部已经消耗物理内存 |
| RSS | 当前驻留物理内存的页 | 多进程 RSS 相加一定无重复 |
| PSS | 将共享页按共享者分摊 | 与虚拟地址空间大小相同 |
| Swap | 被换出到交换空间的匿名页等 | 任意缺页都来自 Swap |

Java 的 `-Xmx` 只限制堆，线程栈、元空间、直接内存与本地库也消耗进程资源。容器内存超限时可能被系统终止，未必产生 Java 堆 OOM。

## 五、面试简答与追问

**简答：** 虚拟内存提供隔离与映射，分页通过页表和 TLB 完成翻译，按需分配与换页让物理内存得到更灵活的使用。

**追问：为什么共享内存能跨进程？** 不同进程的虚拟地址可以映射到同一组物理页，地址数值不需要相同。

# 页面置换算法

## 一、什么时候需要置换

当需要新的物理页而空闲页不足时，系统可能回收现有页面。文件支持的干净页可丢弃后重新读取；脏页可能需要写回；匿名页在可用交换机制下可换出。

页面置换的核心问题是：**淘汰哪一页，能减少接下来的缺页？** 它与 JVM 判断对象可达性、释放堆空间是不同层次的机制。

## 二、经典策略

| 算法 | 淘汰规则 | 特点 |
| --- | --- | --- |
| OPT | 最久以后才会访问的页面 | 需要知道未来，用作理论基准 |
| FIFO | 最早进入内存的页面 | 简单，但不考虑使用热度 |
| LRU | 最久没有访问的页面 | 利用时间局部性，精确维护成本高 |
| Clock | 扫描引用位，给访问过的页第二次机会 | 以较低成本近似近期使用情况 |

Clock 常见模型中，指针遇到引用位为 1 的页就清零并前进，遇到为 0 的页则选为候选。实际系统还会结合脏页、活跃度、回收成本等因素，不只依据一个位。

## 三、FIFO 的 Belady 异常

对访问序列 `1 2 3 4 1 2 5 1 2 3 4 5`，FIFO 使用 3 个页框会缺页 9 次，增加到 4 个页框却缺页 10 次。这说明更多内存不保证某个置换策略下的缺页数单调下降。

理论上的 LRU 和 OPT 具有栈性质，较小容量的驻留集合可包含在较大容量集合中，因此不会出现这一类异常。不要把所有近似 LRU 策略都直接等同于精确 LRU。

## 四、工作集与抖动

工作集可以理解为任务近期持续使用的一组页面。若许多任务的工作集合计超过可用内存，页面反复换入换出，大量时间花在缺页与 IO 上，称为内存抖动。

表现可能是请求延迟飙升、主要缺页增加和磁盘繁忙。处理应减少内存压力、限制并发或增加合适容量，而不是只扩大 Java 堆；堆挤占其他内存还可能使问题加重。

## 五、面试简答与追问

**简答：** OPT 是不可在线实现的基准，FIFO 简单但可能有 Belady 异常，LRU 利用局部性，Clock 降低精确维护开销。

**追问：缓存 LRU 与操作系统置换一样吗？** 思路类似，但操作系统还涉及硬件访问位、脏页写回与不同页类型，代价模型更复杂。

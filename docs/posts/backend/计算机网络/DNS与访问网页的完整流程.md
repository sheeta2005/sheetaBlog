# DNS 与访问网页的完整流程

## 一、DNS 如何得到地址

浏览器和操作系统可能先检查本地缓存或配置，再向递归解析器查询。解析器可使用缓存，也可向根、顶级域和权威服务器逐步获得结果。

**递归查询** 请求对方负责返回最终结果或错误；**迭代查询** 中，服务器可返回下一步应询问的服务器信息。客户端向递归解析器发起查询，不等于根服务器也替它递归完成全部工作。

## 二、常见记录与缓存

| 记录 | 用途 |
| --- | --- |
| A | IPv4 地址 |
| AAAA | IPv6 地址 |
| CNAME | 名称别名，需要继续解析目标名称 |
| MX | 邮件交换服务器 |
| NS | 区域的权威名称服务器 |

TTL 控制记录可缓存的时间，缓存可能在不同层具有不同剩余寿命。修改 DNS 不保证全世界立即切换，也不能简单认为访问者永远固定在某一个 IP。

DNS 可使用 UDP 或 TCP；截断响应等情况可能转用 TCP。DNS over HTTPS/TLS 改变的是与解析器通信的方式，不能把所有解析都说成固定“UDP 53 端口”。

## 三、一次 HTTPS 访问的链路

1. 浏览器解析 URL，检查缓存、重定向、Service Worker 等可能的路径。
2. 若没有可复用连接，解析域名并选择可达地址。
3. HTTP/1.1 或 HTTP/2 常先建立 TCP，再协商 TLS；HTTP/3 则走 QUIC 路径。
4. 发送 HTTP 请求，经代理、负载均衡或 CDN 到达应用。
5. 应用执行鉴权、业务和数据访问，返回状态、头部与响应体。
6. 浏览器解析文档与样式、加载资源，进行布局、绘制和合成。

这些阶段可以重叠、复用或被缓存跳过。不是每次打开网页都重新 DNS、握手并下载所有资源。

## 四、按阶段排查慢请求

域名解析慢，检查解析器与缓存；连接慢，检查网络和监听；TLS 慢，检查握手与证书链；首字节慢，检查代理、应用和数据库；下载或渲染慢，再检查响应体、资源与前端执行。

首字节时间不是纯服务器业务耗时，包含网络等阶段。浏览器时间线、服务端请求日志和链路追踪应相互对应，避免只看一个总耗时。

## 五、面试简答与追问

**简答：** DNS 将名字解析为可用地址，后续经过连接、安全协商、HTTP、服务端处理与浏览器渲染。缓存和连接复用会改变实际路径。

**追问：拿到 IP 就能直接用 HTTPS 访问吗？** 还要匹配目标服务、HTTP 主机信息与证书身份；用 IP 替代域名可能造成证书名称验证失败。

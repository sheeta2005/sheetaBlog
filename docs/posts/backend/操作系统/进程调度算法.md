# 进程调度算法

## 一、先明确调度目标

调度器从可运行任务中选择下一个执行对象。目标可能包括吞吐量、公平性、响应速度和满足截止时间，不能只用“平均等待最少”评价所有算法。

周转时间是完成时刻减到达时刻；响应时间是首次得到运行机会减到达时刻。等待时间描述在就绪队列中等待的时间，与等待设备 IO 的时间需要区分。

## 二、经典算法对比

| 算法 | 规则 | 主要问题 |
| --- | --- | --- |
| FCFS | 先到先服务 | 长任务挡住短任务，产生护航效应 |
| SJF | 选择预计执行最短的任务 | 难以知道真实执行时间，长任务可能饥饿 |
| SRTF | 抢占式选择剩余时间最短者 | 需要估计剩余时间，切换可能增加 |
| 时间片轮转 RR | 每次执行一个时间片后轮转 | 时间片过小增加切换，过大降低交互响应 |
| 优先级调度 | 优先运行高优先级任务 | 低优先级饥饿、优先级反转 |
| 多级反馈队列 MLFQ | 按运行行为动态调整队列 | 规则和周期性提升需要协调 |

SJF 的平均等待时间优势建立在给定任务集合和已知执行时间等假设上，不代表它直接适用于未知请求的在线服务。

## 三、一个时间片例子

三个同时到达的任务需要 8、2、2 个单位 CPU 时间。FCFS 若先执行 8 的任务，后两个要等待 8 和 10；RR 以 2 为时间片时，短任务更早得到第一次运行机会，但长任务会被多次切分。

这里忽略切换开销，目的是比较响应与周转。真实系统不能只通过不断缩小时间片改善所有指标。

## 四、饥饿与优先级反转

饥饿指任务长期得不到资源，可通过等待越久优先级越高的老化或周期性提升缓解。

优先级反转是高优先级任务等待低优先级任务持有的锁，而中优先级任务阻碍低优先级任务释放锁。优先级继承可暂时提升锁持有者的优先级，帮助完成释放。

这些是通用模型；Linux 的具体调度实现会随版本演进，不能把课堂上的 MLFQ 直接当成当前 Linux 的全部调度机制。

## 五、面试简答与追问

**简答：** 调度在公平、响应与吞吐之间取舍。轮转改善首次响应，短任务优先依赖估计，多级反馈依据行为动态分配机会。

**追问：Java 线程优先级能保证执行顺序吗？** 不能。它受到 JVM 与操作系统映射、调度策略影响，业务顺序应使用同步机制表达。

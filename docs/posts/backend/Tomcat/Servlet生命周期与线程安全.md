# Servlet 生命周期与线程安全

## 一、三个关键阶段

容器负责创建 Servlet 实例，调用 `init` 完成初始化，然后才能让它处理请求。请求通过 `service` 进入；HttpServlet 再按方法分发给 `doGet`、`doPost` 等。

卸载或正常停止时调用 `destroy`，释放组件拥有的资源。进程被强制终止时不能保证正常完成销毁，不能把关键业务持久化全部寄托于此。

`load-on-startup` 可让 Servlet 在应用启动时初始化；否则可能按首次请求初始化。初始化一次是相对某个实例和生命周期而言，重部署后可以有新的实例。

## 二、为什么实例字段可能不安全

容器通常复用 Servlet 实例处理多个请求，并可能同时调用它的服务方法。实例字段会被这些请求共享，普通递增、非线程安全集合或共享临时参数都会产生竞态。

```java
// 不安全示例：多个请求共享字段，读改写并非原子操作。
private int visits;
// 服务方法中执行 visits++ 可能丢失更新。
```

如果只需要当前请求的数据，把它放在请求范围的局部变量或请求属性中；如果确实需要共享计数，再按业务选择原子类或同步。局部变量引用一个共享可变对象，仍可能发生线程安全问题。

## 三、不同数据范围

| 范围 | 共享情况 | 注意点 |
| --- | --- | --- |
| Servlet 实例字段 | 同实例的请求共享 | 需要并发控制 |
| ServletContext 属性 | 同应用内共享 | 容器保存属性不保证属性对象线程安全 |
| HttpSession 属性 | 同会话多请求可并发 | 同一用户也会有并发请求 |
| 请求与局部数据 | 常用于单请求 | 异步访问、共享引用仍需协调 |

不能因“一个用户一个 Session”就忽略浏览器多标签或并发接口调用。Session 中的余额或购物车更新也要考虑原子性与持久化规则。

## 四、异步和资源释放

Servlet 异步请求需要在合适时机完成，并处理超时和错误。不能假设初始 `service` 返回后请求对象立刻无效，也不能在请求结束后无限期继续使用容器对象。

应用自行创建的执行器和监听器应在生命周期结束时释放；ThreadLocal 使用后及时移除，避免线程池复用时污染下一个请求或保留旧加载器。

## 五、面试简答与追问

**简答：** Servlet 由容器初始化、复用处理请求并销毁；同实例可被并发调用，实例字段、会话与应用共享状态必须单独保证安全。

**追问：把整个 service 加 synchronized 可以吗？** 可以串行化相应实例的调用，但容易降低吞吐，并不能替数据库或其他实例提供全局一致性。

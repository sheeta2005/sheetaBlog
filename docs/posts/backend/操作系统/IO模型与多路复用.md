# IO 模型与多路复用

## 一、把等待与执行分开

网络读取通常要等待数据到达，再把数据交给应用。阻塞读取在不能完成时让调用线程等待；非阻塞读取在当前无数据时立即返回，例如 `EAGAIN`，应用决定何时重试。

**非阻塞不等于异步。** 调用者仍可能亲自执行读取。异步 IO 通常把操作提交后，通过完成事件获得结果；要区分“可以读了”和“已经读完了”。

## 二、多路复用解决什么问题

如果每个空闲连接都占用一条等待线程，大量连接会增加线程资源开销。多路复用让一条线程等待多个描述符的就绪事件，再处理有活动的连接。

| 机制 | 主要区别 | 注意点 |
| --- | --- | --- |
| select | 每次提供描述符集合，返回就绪集合 | 常见实现受 FD_SETSIZE 限制 |
| poll | 使用描述符数组 | 每次调用仍需提交和检查集合 |
| epoll | 注册关注对象，再取得就绪事件 | 适合大量连接、少量活跃的场景 |

不能用“epoll 在所有情况下都是 O(1)”概括其全部成本。注册、唤醒、事件数量、处理业务和内核同步都影响性能。

## 三、LT 与 ET

**水平触发 LT：** 只要描述符仍处于就绪状态，后续等待仍可报告事件。**边缘触发 ET：** 关注状态变化，通常配合非阻塞 IO，持续读写直到返回 `EAGAIN`。

例如收到 8 KB 数据，只读走 1 KB 就返回事件循环，ET 模式下不能假设剩余 7 KB 会再次触发通知。正确循环还需处理 EOF、错误与写缓冲状态。

## 四、Reactor 与业务线程

Reactor 使用就绪事件分发读写；Proactor 围绕操作完成事件分发结果。实际框架可能组合不同机制，要观察具体实现。

Tomcat NIO 的连接事件处理不意味着 Servlet 业务天然无阻塞。若在处理线程中等待慢 SQL 或调用外部服务，仍会占用工作线程。Java NIO 是 API 分类，也不能简单对应为操作系统的异步完成模型。

## 五、面试简答与追问

**简答：** 阻塞描述等待行为，非阻塞允许立即返回，多路复用集中等待多个就绪对象，异步 IO 关注操作完成。epoll 的优势取决于连接与事件分布。

**追问：事件循环为什么不能做长时间计算？** 它会推迟其他连接事件处理，需要把耗时任务移到受容量约束的工作线程或分解执行。

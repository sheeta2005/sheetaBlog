# 对象创建与内存分配

## 一、new 背后发生什么

遇到创建对象的字节码时，JVM 需要确保相关类已按要求初始化，为实例获得存储空间，使字段具备默认值，再执行构造器完成业务初始化。

规范保证字段默认值与初始化语义，具体对象头、对齐和分配路径由 JVM 实现决定。不能把 HotSpot 的对象布局当作 Java 语言对所有平台的固定承诺。

## 二、堆分配如何处理竞争

内存连续且可快速推进时，可通过移动分配指针分配；有不同大小空闲块时，需要相应的空闲空间管理。多个线程共享分配区域，必须保证申请结果不重叠。

HotSpot 可为线程提供 **TLAB**，即线程本地分配缓冲区。线程在自己的缓冲区内分配多数小对象，减少共享区域竞争。TLAB 仍位于堆中，不是线程栈，也不改变对象被其他线程引用的可能性。

## 三、年轻代、晋升与大对象

普通对象在分代回收器下常从年轻代分配，经历回收后存活对象可能晋升。晋升不只由一个固定年龄决定，还受收集器、空间和自适应策略影响。

G1 的 Humongous 对象会使用大对象 Region，归属于老年代。JDK 21 HotSpot 源码按对象总大小严格大于 Region 一半判断；要计入对象头与对齐，不能只看数组有效载荷。不是所有对象都先落在 Eden。

不要照搬旧收集器的参数来解释 G1 分配，也不能把“新生代满了”作为所有垃圾回收事件的唯一原因。

## 四、逃逸分析与标量替换

```java
// 若对象及字段满足优化条件，JIT 可能消除实例分配；具体结果取决于编译情况。
static int sum(int x, int y) {
    Point point = new Point(x, y);
    return point.x() + point.y();
}
record Point(int x, int y) {}
```

JIT 判断对象不需要以完整实例形式存在时，可能把它拆为标量并消除分配。更准确的说法是“对象分配可能被优化掉”，不是“所有不逃逸对象都会完整放进栈中”。返回对象、存入全局结构或优化条件不足时，不能假定分配一定消失。

## 五、面试简答与追问

**简答：** 对象创建涉及类初始化检查、存储分配、默认值与构造初始化。TLAB 降低分配竞争；存活与大对象路径依赖收集器，JIT 还可能消除实际分配。

**追问：对象多就一定内存泄漏吗？** 不是。高分配速率增加回收压力；长期被不必要引用保留才可能形成泄漏，要结合回收后存活量判断。
